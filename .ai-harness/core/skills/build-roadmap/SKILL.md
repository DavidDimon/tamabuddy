# Build a roadmap

Read `../../../domains/product-delivery/docs/roadmap-contract.md`, then inspect the current implementation, owning domain, accepted decisions, and known risks. Use `../../templates/roadmap.md` when a durable roadmap artifact is requested.

Sequence milestones by dependency and learning. Prefer a narrow vertical proof before broad migration. Give every milestone an observable exit and identify decisions it unlocks. Do not present speculative dates as commitments; label estimates and assumptions when the user needs scheduling.

Keep required outcomes separate from optional improvements. Use the task skill afterward only when the user requests task-level decomposition.
